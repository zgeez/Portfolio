EEG Acquisition & Neurofeedback System

An 8-channel EEG acquisition and neurofeedback prototype built around the TI ADS1299 analog front end and an ESP32-S3 SPI bridge, with a MATLAB acquisition/processing pipeline and a supervised Rest-vs-Task Random Forest classifier that reaches 83% block-classification accuracy on focus-state recordings.

Project Overview

Sustained engagement is hard to measure in a classroom: the usual feedback is delayed, observational, and non-adaptive. This project asked a narrower engineering question: can a locally-processed, low-cost 8-channel EEG rig reliably separate rest from cognitive task? Answering it meant building the entire chain: analog front end, embedded firmware, acquisition software, labeled data collection, a supervised model, and a teacher-facing display.

This is an engineering proof-of-concept. It does not diagnose or treat any condition, and its output is a Rest-vs-Task classification result used as a cautious proxy for task engagement, not a measure of attention or ability.

Hardware & Firmware

The analog front end is the TI ADS1299EEG-FE, an eight-channel, 24-bit simultaneous-sampling biopotential ADC with integrated PGAs and a bias-drive amplifier. Rather than use the stock DSP motherboard path, I brought the board up against an ESP32-S3 acting as SPI master: the MCU configures the channel registers, starts continuous conversion, reads each 27-byte frame on the DRDY interrupt, and forwards framed binary packets over USB serial at 250 Hz.

Firmware Responsibilities

SPI Bring-Up

  • Register configuration for all 8 channels
  • Gain, reference buffer, and bias-drive setup
  • RDATAC continuous-read mode
  • Clock/timing validation with logic analysis

Streaming

  • DRDY-triggered frame capture
  • Status word + 8 × 24-bit signed samples
  • Framed binary packets over USB serial
  • Drop counting for stream integrity

MATLAB Acquisition & Processing

MATLAB is the core of the workflow: it opens the serial port, parses the binary ADS1299 packets, converts raw counts to microvolts, applies the real-time filter chain, computes spectral features, launches the cognitive tasks, writes synchronized markers, and logs every run to disk in a reproducible folder structure.

Data Collection

Supervised training needed clean labels, so every recording is structured as alternating rest and task blocks with markers written by the task launcher itself, where Rest = 0 and Task = 1. Marker alignment turned out to be one of the highest-leverage details in the whole project: misaligned blocks silently poison the training set.

Rest-vs-Task Classifier

The classifier is a Random Forest over spectral features from 5-second windows with a 2.5-second step. Each window contributes Welch-PSD-derived bandpower features across all eight channels; artifact and outlier rejection runs before inference. The model outputs P(Task), and a tuned threshold converts that probability into a Rest-vs-Task decision. Block accuracy, the metric that matters for this use case, aggregates window-level predictions across a full task or rest block.

Teacher Dashboard & Student View

The Electron/React dashboard is the instructor side of the prototype. It separates system controls from what a student sees: the teacher gets device state, engagement-proxy history, calibration, and session scripting, while the student view shows only the current classroom prompt.

Privacy, Safety & Scope

Local-First Processing

Acquisition, markers, inference, and display all run locally. No cloud processing is required for the core workflow, which limits exposure of sensitive EEG and session data.

No Diagnostic Claims

The system does not diagnose or treat ADHD or any other condition. Its output is an engineering classification result, not a medical conclusion.

Data Minimization

Only the data needed for testing, training, and validation is retained, using anonymous subject and session labels.

Supervised Use Only

The prototype is used under supervision within senior-design constraints. Any classroom or child-facing deployment would require consent procedures and institutional review.

Future Work

  • Broader dataset: collect across more subjects to test cross-subject generalization
  • Live inference: integrate the latest exported model directly into the dashboard path
  • Artifact handling: stronger rejection for blink and motion transients
  • Setup ergonomics: improve cap comfort and reduce time-to-first-signal
  • Validation: supervised, IRB-style usability testing before any real classroom use
