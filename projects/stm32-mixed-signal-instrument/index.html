STM32 Mixed-Signal Instrument

A USB bench instrument built on an STM32F407 Discovery board and paired with a desktop application. One device provides a 2-channel arbitrary waveform generator, a 2-channel oscilloscope, an 8-channel logic analyzer, and a combined mode that puts analog and digital capture on a single shared timeline, with a measured start skew of -120 ns.

Firmware in C on FreeRTOS · Desktop application in Python with PySide6

Repository → · Download the application and firmware →

Project Overview

A student who wants to see a signal usually needs three separate instruments, and the bench that has all three is the one they cannot take home. This project asked whether one board they already own can do the work: generate, capture, and correlate analog and digital signals from a single device, driven by an application on the host.

The answer required the whole chain. Firmware in C on FreeRTOS runs four tasks and coordinates seven concurrent DMA streams across the DAC, dual ADC, and GPIO sampling. A versioned binary protocol carries 28 commands over USB CDC. A PySide6 desktop application configures the outputs, pulls captures, measures them, and decodes serial traffic. It ships as a single Windows executable that flashes the board's firmware itself.

This is an unprotected low-voltage prototype, not a product. Inputs must stay within the board's own supply and reference limits: no mains, negative-voltage, or automotive inputs.

One Timeline for Analog and Digital

The distinctive part of the instrument is not the instrument count, it is that two capture paths running at different rates can be compared against each other. Every timer on the device divides the same crystal, which is what makes a shared timebase possible in the first place. TIM1's trigger output releases a slaved TIM2, so a logic capture and an analog capture start from one hardware event rather than from two software commands that happen to be close together.

Each stream then reports where its own window begins relative to that shared start, and the application draws both against one axis with zero at the trigger. Only one stream holds the trigger; the other free-runs and is placed by index. Where the two windows do not overlap, the display says so rather than leaving the reader to infer it.

A Shared Start Is Not a Shared Sampling Instant

Measured skew between the two paths is -120 ns. That figure is not noise and it is not a defect: it matches the ADC's 143 ns sample-and-hold aperture, so the number was traced to a specific mechanism rather than left as a residual. No jitter is resolvable above the sampling quantization. The skew is measured against the device's own reference output, which shares the sampler's clock, so it bounds the two acquisition paths against each other rather than against an independent time base.

The Instruments

Waveform Generator

  • 2 outputs on PA4 and PA5
  • 1 Hz to 20 kHz, 93.13 µHz step
  • Sine, triangle, square, sawtooth, DC
  • 2–256 entry arbitrary tables
  • Circular DMA, 1.28 ms refill deadline

Oscilloscope

  • 2 inputs on PC4 and PC5
  • 1 MS/s on two channels
  • 64 to 2048 simultaneous sample pairs
  • Free-run, rising and falling triggers
  • Adjustable pre-trigger position

Logic Analyzer

  • 8 inputs on PE7 to PE14
  • 9.882 MS/s, sampled together
  • 64 to 4096 samples
  • Edge and masked-pattern triggers
  • UART, SPI and I2C decoding

The generator uses a 32-bit phase accumulator clocked at 400 kS/s, which gives a frequency step of 93.13 µHz, finer than the millihertz the protocol accepts. A refill that misses its half faults and stops the timer rather than repeating stale samples, so a missed deadline is reported instead of quietly producing a wrong waveform. Scope and logic acquisition are mutually exclusive; the generator runs alongside either.

Firmware & Host Protocol

🔹 Device

  • STM32F407VGT6, ARM Cortex-M4
  • Bare-metal C with FreeRTOS, four tasks
  • 7 concurrent DMA streams
  • DAC, dual ADC and GPIO sampling
  • Chained timers for the shared start

🔹 Link

  • Versioned binary protocol, 28 commands
  • COBS framing over USB CDC
  • Native CDC port, separate from ST-LINK
  • Version mismatch named, not guessed at
  • PySide6 desktop application and a CLI

Waveform refill, acquisition, USB control and status are separated into their own FreeRTOS tasks. Board checks cover concurrent load, stack headroom, refill latency, fault recovery and USB backpressure. The application warns when firmware is older than it expects, naming both versions and staying connected, on the reasoning that a mismatch may not matter to what you are doing but you should know it is there.

Finding a 20 ms Latency Floor

Every request to the device was taking almost exactly 20 ms, and a capture transfer was always an exact multiple of that figure. An exact multiple is the useful clue: a genuine throughput limit does not quantize that cleanly, but a timeout does.

The cause was a single missing call. tasks_notify_control() was defined and declared but never called from the CDC callbacks, so the control task ran only on its 10 ms idle timeout and reception was not rearmed until it did. Every request waited for that timer instead of the interrupt that should have woken it. The transmit-complete callback had the same gap. Calling the notify from both, inside the CubeMX user-code regions so the fix survives regeneration, removed the floor.

Measured Rather Than Declared

The part of this project that took the most work is the part that does not appear in the feature list: showing that the instrument does what it says. Sample loss is the clearest example. Rather than assume the DMA paths keep up, loss was bounded below 1 in 81,000 samples with no isolated drops, measured against an on-board timer reference across the worst of four rates, 30 captures each.

Stated Limits

Analog accuracyAbsolute amplitude accuracy, distortion and bandwidth are uncharacterized.Loopback alone cannot isolate which path contributes an error, and PA4 is loaded by the board's audio codec connection.

Voltage and frequency figures are measured against the board's own references. They are not calibrated or certified against a traceable standard.
